# 插件兼容声明用 engines.dsh，范围从 0.2.1-rc.2 起

DSH 0.2.1-alpha.3 起，安装与 profile 启动优先读包自己的 `engines.dsh`；只有缺失时才回退到 `@deepseek-ai/dsh*` peer 范围，拒绝记录里的字段也从 `peers` 改名为 `requirements`。本包因此声明 `"engines": { "dsh": ">=0.2.1-rc.2 <0.3.0" }`，并把 `dsh-system-prompt` 的 peer 同步放宽到同一范围；`cordis` peer 保留，只作为运行时共享实例的说明。

没有选另外三条：只把 peer 钉到当前宿主（`0.2.1-rc.4`），那样每次 DSH 升级都要改包，且新规则下 peer 已不是主判据；用官方示例的 `>=0.2.0 <0.3.0`，它更宽，但按 npm semver 默认规则实测不匹配 `0.2.1-rc.4`（`satisfies` 为 false），无法覆盖当前宿主；不声明兼容范围，则会被默认的 peer 规则挡住。

范围起点取 `0.2.1-rc.2`，因为那是本包验证过的最低宿主。上界 `<0.3.0` 把后续 0.2.x 稳定版都放进来，同时挡住 0.3 的破坏性变更。代价是范围外的 0.2.2 预发布会被拒绝，届时需要重新评估并改包。
